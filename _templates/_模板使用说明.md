# 模板使用说明

`_templates/` 下每个文件都是一份**可复制的最小骨架**：第 1 行就是 front-matter（`---` 开头，8 个字段齐全），该类型的必填章节标题已按 [`SCHEMA.md`](../SCHEMA.md) §4 逐字写好，每个标题下面有一条斜体提示说明这一节该写什么、常见错误是什么。斜体提示是**给你看的**，写完内容后连同 `<标题>` 这类占位符一起删掉。

写新页面时不要手建空文件。

## 一、类型 → 模板 → 目录对照

| 类型 | 模板文件 | 目标目录 | 必填章节数 | 写进 front-matter 的 `type` |
|---|---|---|---|---|
| 技术模块 | [`技术模块模板.md`](技术模块模板.md) | `docs/部门/<部门>/技术模块/` | 8 | `技术模块` |
| 项目实践 | [`项目README模板.md`](项目README模板.md) | `docs/部门/<部门>/项目实践/` | 11 | `项目实践` |
| 技术经验 | [`踩坑记录模板.md`](踩坑记录模板.md) | `docs/部门/<部门>/技术经验/` | 6 | `技术经验` |
| 学习课程 | [`课程模板.md`](课程模板.md) | `docs/部门/<部门>/学习课程/` | 7 | `学习课程` |
| 部门介绍 | [`部门介绍模板.md`](部门介绍模板.md) | `docs/部门/<部门>/`（README.md） | 9 个字段 | `部门介绍` |
| 硬件资料 | [`硬件资料模板.md`](硬件资料模板.md) | `docs/部门/<部门>/技术模块/硬件/` | 8 | `技术模块` |
| 项目复盘 | [`项目复盘模板.md`](项目复盘模板.md) | `docs/部门/<部门>/历史与交接/` | 5 | `项目实践` |
| 历史与交接 | [`历史与交接模板.md`](历史与交接模板.md) | `docs/部门/<部门>/历史与交接/` | 3 类记录 | `历史与交接` |

**最后两列的差别要留意**：`type` 只能取 [`SCHEMA.md`](../SCHEMA.md) §3.1 里的 9 个值，而「硬件资料」「项目复盘」不在其中——它们的正文结构确实和 `技术模块` / `项目实践` 不一样，但类型上按就近归并，分别写成 `技术模块`、`项目实践`（`scripts/new.mjs` 已经这么填）。这两类页面的**章节校验在 `_schema/frontmatter.json` 的 `skipSections` 里被豁免**（路径分别是 `技术模块/硬件/*.md` 与 `历史与交接/*复盘.md`），front-matter 的 8 个字段照校不误。也就是说：照模板写就好，不要去改 `type` 来绕过检查。

**不在上面的内容怎么放**：拿不准属于哪一类时，用 [`CONTRIBUTING.md`](../CONTRIBUTING.md) §4 的六个问句判断；确实不属于任何一类的（会议纪要、临时笔记）先放 `raw/`，编译成正式文档时再套模板。

## 二、用脚本生成（推荐）

```text
node scripts/new.mjs <类型> <目标路径>
```

`<类型>` 取上表第一列；`<目标路径>` 写不带 `.md` 后缀的路径，脚本会建目录、复制模板、把 `更新` 填成今天。四个实例：

```powershell
# 技术模块
node scripts/new.mjs 技术模块 docs/部门/终端服务部/技术模块/Ansible批量配置

# 项目实践
node scripts/new.mjs 项目实践 docs/部门/终端服务部/项目实践/机房监控大屏

# 技术经验
node scripts/new.mjs 技术经验 docs/部门/终端服务部/技术经验/磁盘inode耗尽

# 学习课程
node scripts/new.mjs 学习课程 docs/部门/终端服务部/学习课程/第02课-容器基础
```

脚本跑完后文件已经存在，直接打开写内容，**不要再手工复制一遍模板**。

不想用脚本时也可以手动复制模板文件到目标目录再改名，后面五件事一样要做。

## 三、复制模板后必做的 5 件事

1. **填 front-matter**。这是第一件、也是唯一一件脚本不会替你做的事：**模板的第 1 行就是 `---`**，上面那 8 行 front-matter 已经是成品该有的形状，`type` 与 `部门` 已经填好，要你改的只有四处——`title` 换成真实标题、`维护人` 换成你的 GitHub 用户名、`更新` 填今天、`状态` 按实际完成度选 `草稿` / `可用` / `待修订`（`tags` 选填）。字段清单见 [`SCHEMA.md`](../SCHEMA.md) §3。**替换 `<标题>`、`<你的GitHub用户名>` 这类尖括号占位符，不要留着进 PR**——`scripts/check-frontmatter.mjs` 会把它们判成不合法取值。
2. **保留全部小节标题**。模板里的每个 `##` 标题都必须留在成品里，顺序一致、文字逐字一致。某一节确实没有内容时，标题下面写"不适用"并加一句为什么，**不许删标题**——空白结构比缺失结构更容易复用，下一个项目可能就用得上这一节。
3. **按「四能」自查**。能理解 / 能学习 / 能复现 / 能延续，四条逐条过一遍。展开说明见下面第五节，这是最容易被退回的一条。
4. **跑脱敏自检**。`node scripts/check-secrets.mjs`，再对照 [`SCHEMA.md`](../SCHEMA.md) 与 [`CONTRIBUTING.md`](../CONTRIBUTING.md) §2.3 的表人工看一遍。脚本只认正则，`实验室 433 房间的 Dell 服务器` 这类它扫不出来，**必须靠眼睛**。
5. **把新文件加进 [`nav.片段.yml`](../nav.片段.yml)**。不加的话站点里点不到这个页面，等于没写。加完跑一次：

   ```powershell
   node scripts\check-frontmatter.mjs
   node scripts\check-secrets.mjs
   npx markdownlint-cli2 "docs/**/*.md"
   ```

## 四、「不适用」怎么写

不适用 ≠ 可以删。正确写法是保留标题，正文写清楚为什么没有：

```markdown
## 五、硬件环境

不适用：该项目全部跑在已有的容器平台上，没有独立硬件。
```

反面写法（会被 Review 退回）：

- 直接删掉整个标题。
- 写"无"、"略"、"见上文"。
- 标题留着但正文空白。

## 五、「四能」自检展开

这四条是文档质量的唯一验收标准，写在 [`CONTRIBUTING.md`](../CONTRIBUTING.md) §2.1，这里说清楚怎么算过。

### 1. 能理解

外行读一遍知道在说什么。

- **判据**：随便找一个不参与这个项目的人读第一段，他能不能说出"这篇是做什么的"。
- **做法**：缩写第一次出现时展开；术语用一句话解释或链到 `基础知识/`；一上来就讲背景和用途，不要从技术细节开头。
- **常见错误**：默认读者知道上下文，直接写"把原来的方案换成新的"，但从没说过"原来"是什么。

### 2. 能学习

有原理、有步骤、有例子，不是只有结论。

- **判据**：读完知道**为什么这么做**，而不是只知道"照这个抄"。
- **做法**：技术模块写清工作原理，项目实践写清技术路线里的取舍理由，经验帖写清根因的成因链。
- **常见错误**：只贴一段配置或代码，不说它解决什么问题、参数为什么取这个值。

### 3. 能复现

步骤可复制粘贴执行，命令带上下文。

- **判据**：一个没做过这件事的人，照着从头做一遍能出一样的结果。
- **做法**：每条命令标明**在哪台机器、什么权限、什么目录下**执行，贴出预期输出，把内网地址这类真实值换成 `<内网IP>` 这类占位符，但仍保留命令形状。
- **常见错误**："以上步骤略"、"参考官方文档"、命令缺前缀、结果靠描述不靠粘贴。

### 4. 能延续

半年后另一个人接手能看懂并继续做。

- **判据**：只看这一篇（不看聊天记录、不看作者），能接着往下做。
- **做法**：写 `已知问题` 和 `后续方向`；把当时的取舍和限制写出来；不留"待补充"却没有待补清单。
- **常见错误**：只写成功路径，不写踩过的坑和已知缺陷，接手的人要把坑重踩一遍。

## 六、模板里出现的占位符

模板和示例里不允许出现真实内网信息，用下面这套写法：

| 占位符 | 代替 |
|---|---|
| `<内网IP>` / `<组网IP>` | `10.x`、`192.168.x`、`172.16–31.x`、`100.x` |
| `<设备名>` / `<主机名>` | 真实主机名、序列号 |
| `<域名>` / `<tailnet域名>` | 私有域名、`*.ts.net` |
| `<用户名>` / `<你的GitHub用户名>` | 真实姓名、邮箱、账号 |
| `<路径>` / `<输出目录>` | 机器相关的本地绝对路径 |
| `<序列号>` | 设备序列号 |

凭据、token、私钥全文**任何情况下都不入库**，只写"在哪、谁管"。
