# <主题> · 变动记录

> 本文件是 `type: 历史与交接` 的模板骨架，复制到 `docs/部门/<部门>/历史与交接/<主题>.md`。**顶部的 front-matter 就是成品该有的样子**：`title` 换成变动主题、`type` 保持 `历史与交接`、`维护人` 换成你的 GitHub 用户名、`更新` 填成今天。
>
> 按**三类记录里符合的那一类**逐段写；不涉及的那两类保留标题写"不适用"。三类记录里的小节（1.1–1.6、2.1–2.5、3.1–3.7）按需保留，缺的信息写"待确认"而不是留空。
>
> 记法的总原则：**只追加、不覆盖**。写错了再加一条更正记录，不要抹掉原来的内容——交接记录的价值就在于能看出"什么时候谁以为是什么"。

> 变动完成后必须同步的动作见本页末尾「四、变动的收尾动作」。

## 一、人员变动记录

*一个人加入、离开或换岗时写这一节。每类变动都把下面这些小节点齐。不涉及人员变动时整节写"不适用"。*

### 1.1 背景

*写清是谁、什么时间生效、原因（入职 / 毕业 / 转岗 / 长期外出）。人名用 `<用户名>` 占位，真实姓名放内部库。*

### 1.2 变动前负责的范围

*逐条列出：负责哪些页面、哪些服务、哪些设备、哪些账号或权限的持有。**每条都要给页面路径或服务名**，不要写"负责服务器相关"——接手人无法据此找全。*

### 1.3 变动后归谁

*逐条对应上一条写新负责人。暂时没人接的写"暂无人接手（风险：……）"，这类条目要在「1.6 后续跟踪」里出现。*

### 1.4 交接内容清单

*写清实际交出去的东西：文档所有权、账号与权限（**凭据本身不入库**，只写交接方式与保管人）、未完成的工作与当前进度、口头约定与历史决策背景。有一项没交成要写明原因。*

### 1.5 接手人确认

*接手人逐条确认收到后的记录：确认日期、确认方式（当面 / 线上过了一遍）、哪些条目还有疑问、约定多久内反馈。没有确认动作的交接视为未完成。*

### 1.6 后续跟踪

*需要盯的遗留项：待处理的故障、待续期的账号、待补的文档。每条给负责人与期望时间。*

## 二、设备变动记录

*设备上架、下架、迁移、报废、借用、换件时写这一节。不涉及设备变动时整节写"不适用"。*

### 2.1 背景

*设备名称（用 `<设备名>`，与 `技术模块/硬件/` 下的页面一致）、变动类型、时间、原因（扩容 / 故障 / 报废 / 外借 / 场地调整）。*

### 2.2 变动内容

*写清从什么状态变成什么状态：位置、归属、用途、配置是否改动。位置在公开库写到「机房 / 实验室」这一层，精确机位放内部库。*

### 2.3 影响范围

*谁在用这台设备、上面跑着什么服务、变动期间是否有中断、需要谁提前知道。有中断的写清中断时长和恢复方式。*

### 2.4 需要同步更新的页面

*列出要跟着改的文档：硬件资料页、项目实践页、`nav.片段.yml`、服务目录。给出相对路径，让接手人直接点进去改。*

### 2.5 接手人确认

*确认设备实物位置、附件是否齐全、台账是否已改。缺附件要写清缺什么。*

## 三、系统迁移记录

*服务换机器、换域名、换数据存储、换部署方式时写这一节。不涉及系统迁移时整节写"不适用"。*

### 3.1 背景

*迁移的是什么系统、覆盖哪些服务、为什么迁（机器到期 / 性能不够 / 整合 / 合规要求）。*

### 3.2 迁移前状态

*写清迁移前的真实情况：跑在哪台机器、数据在哪、对外地址是什么（**占位符**）、有哪些外部依赖与调用方、有哪些定时任务。这一节是回滚的依据，必须完整。*

### 3.3 迁移方案与步骤

*写清迁移怎么做：停机窗口、数据备份与校验方式、切换顺序、DNS / 反代的切换点。按 `项目实践` 的「复现步骤」标准写——命令要能原样粘贴执行，标明在哪台机器。*

### 3.4 迁移后状态

*对应「3.2 迁移前状态」逐条写新值：新机器、新数据位置、新对外地址、新增或去掉的依赖、调用方需要改什么。*

### 3.5 验证与回滚

*写清验证动作与通过标准（业务能不能通、数据条数/校验和对不对、定时任务有没有按时跑），以及回滚的触发条件和回滚步骤。**回滚方案不能只在脑子里**。*

### 3.6 旧环境处置

*旧机器/旧服务是保留（保留到什么时候）、转做他用、还是下架报废。保留期结束后谁负责清理。*

### 3.7 接手人确认

*确认新环境已接管、监控已切、备份任务已在新环境跑过至少一次、旧环境清理时间已记入待办。*

## 四、变动的收尾动作

每次人员 / 设备 / 系统变动之后，逐项做完再关掉这件事：

- [ ] 相关页面的 `维护人` 已转给接手人
- [ ] 相关页面的 `更新` 已改成当天
- [ ] 依赖变了但内容没重写的页面，`状态` 已改成 `待修订`
- [ ] 仓库根的 `nav.片段.yml` 已加入或移出对应条目（这里不写链接：本模板会被复制进章节目录，而部门章必须自包含）
- [ ] 本页已提交，commit message 里写清变动性质
- [ ] 遗留项已写进「后续跟踪」，有负责人和时间
