# raw/ —— 原始素材区

这个目录放**没有整理过的原始素材**，不属于交付内容，也不会被渲染成站点（`mkdocs.yml` 的 `docs_dir` 是 `docs/`）。

## 放什么

```text
raw/
├─ 会议记录/      会议纪要、讨论记录、决议
├─ 聊天记录/      群里讨论出的结论、问答
├─ 厂商手册/      设备与软件的官方手册、数据手册
├─ 实验数据/      跑出来的日志、指标、截图
└─ 交接材料/      离职/换届时交出来的散乱资料
```

## 三条规则

1. **只进不出**：`raw/` 里的东西永远不作为交付物直接给人看，从 `raw/` 到 `docs/` 之间必须有一步**编译**。
2. **编译不是搬运**：搬进 `docs/` 的内容必须落到六类里的一类、带完整 front-matter、并且**把口语记录改写成可复现的步骤**。
3. **编译质量的唯一标准**：没读过 `raw/` 的人能不能独立看懂编译结果。

完整的编译契约见仓库根目录的 `SCHEMA.md` §6。

## 注意：这里不是公开内容

本仓库是公开的，但 `raw/` 里的素材**未做脱敏**，可能包含内网地址、主机名、账号等：

- **不要**把 `raw/` 里的内容原样复制到 `docs/` 下。必须先脱敏、再编译。
- 涉及内部信息的素材，**优先放内部库**，不要把原始件留在这里。
- 提 PR 时如果动了 `raw/`，Review 会看一遍有没有不该进来的东西。

## 这个目录为什么现在还是空的

因为**编译是有人做才有的**。`raw/` 空着表示目前还没有进入编译流程的素材，不代表这一层不需要——它是给"以后有人把一份聊天记录变成一篇技术经验"留的位置。

要开始编译，看仓库根目录的 `CONTRIBUTING.md`。
