## 这个库是怎么组织的

内容分六类，规律很简单：**看文件在哪个目录，就知道它是哪一类。**

```text
基础知识   → 概念是什么（入门）
技术模块   → 一门技术怎么用（一个模块一篇）
学习课程   → 一门课怎么上（含新人上手路径）
项目实践   → 一个项目怎么做（含完整复现步骤）
技术经验   → 一个坑是怎么踩的、后来怎么填的
历史与交接 → 人员、设备、系统的变动记录
```

每一页开头都有一段元信息（写作日期、维护人、可信度状态）。**`状态: 草稿` 的内容不要当成结论**；`状态: 待修订` 表示内容曾经可用，但现在已知过时。

完整的机器可读契约见仓库根目录的 `SCHEMA.md`。

## 两条边界

### 1. 公开库只放能公开的内容

这个仓库是**公开**的。凡是涉及内网地址、服务器台账、真实主机名与域名、账号与凭据位置的内容，都不在这里，而在配套的内部库中。公开页面上会以「内部细节见内部库」的形式留一个提示，而不是留空。

判断标准只有一句：**这段内容落到外面人手里，会不会给实验室添麻烦。**

### 2. 内容不押注平台

实验室主书现在用 MkDocs + GitHub Pages，但它的定位是**总目录**，不收纳正文；本库的正文将来也可能被要求整章并入。所以这个库的做法是：

- 内容全是**纯 Markdown**，没有任何平台专有语法。
- 页面之间只用**相对路径**互链。
- **部门章是完全自包含的**：`docs/部门/终端服务部/` 里不出现任何指向章外的链接，于是它随时能整棵搬走而不产生断链（见仓库根目录的 `并入主书说明.md`）。

仓库根目录同时提供了 MkDocs（`mkdocs.yml`）、GitBook（`SUMMARY.md` + `.gitbook.yaml`）和 LLM 读取（`SCHEMA.md`）三种入口，**换平台不需要动内容**。

## 怎么本地预览

```powershell
python -m venv .venv
.\.venv\Scripts\pip install -r requirements-docs.txt
.\.venv\Scripts\mkdocs serve
```

然后打开 `http://127.0.0.1:8000`。（写成代码块而不是自动链接：链接检查工具会真的去连它，本地服务没起来就报断链。）
