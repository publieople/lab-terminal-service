# VS Code 安装与远程开发

## 一、这页讲什么

本地装个编辑器只解决一半问题：代码在服务器上，改一次要传一次文件，这是最慢的做法。Remote-SSH 把编辑器界面留在本地、代码与运行环境留在服务器，编辑体验与本地一致。

读完能做到：装好 VS Code 并改成中文界面；用 Remote-SSH 连上服务器并打开项目目录；配好端口转发在本地浏览器里看服务器上跑的服务。

## 二、开始之前

| 项 | 内容 |
| --- | --- |
| 版本与日期 | VS Code 1.10x；2026-10-21 核实 |
| 预计耗时 | 20 分钟 |
| 前置 | 能 SSH 登录服务器，见 [SSH](../SSH.md)；服务在 tailnet 内，见 [Tailscale 组网](../Tailscale/01-组网与直连.md) |
| 风险级别 | 低：只装软件与插件 |

## 三、动手做

### 1. 安装

从官网下载对应系统的安装包，或按官方文档用包管理器装。两个版本：Stable 是常规版本，Insiders 是每日构建，只有想提前试新功能时才用 Insiders。

看到这个就算成：`code --version` 打印出版本号与提交号。

### 2. 换成中文界面

1. `Ctrl + Shift + P` 打开命令面板；
2. 输入 `Configure Display Language`；
3. 选 `zh-cn`，按提示重启。

看到这个就算成：重启后菜单与设置项都是中文。

### 3. 装 Remote-SSH 扩展

在扩展面板搜 `Remote - SSH`（发布者 Microsoft）安装。装完左侧活动栏会出现「远程资源管理器」。

看到这个就算成：活动栏出现远程资源管理器图标，命令面板里能搜到 `Remote-SSH: Connect to Host`。

### 4. 配好 SSH 别名

在本地 `~/.ssh/config` 里写一条别名，编辑器与终端共用同一份配置：

```text
Host lab
    HostName <服务器地址>
    User <用户名>
    Port 22
```

看到这个就算成：本地终端 `ssh lab` 能直接登录，不再需要每次输入完整地址。

### 5. 连接到服务器

命令面板 → `Remote-SSH: Connect to Host` → 选 `lab`。首次连接会在服务器上装 VS Code Server，需要能访问外网或由管理员配置离线安装。

看到这个就算成：左下角状态栏显示 `SSH: lab`，文件面板列出服务器上的目录。

### 6. 打开项目目录

`File → Open Folder`，选服务器上的代码目录。把常用目录加进工作区，下次连接后直接恢复。

看到这个就算成：编辑器里看到的是服务器上的文件，改动直接落在服务器。

### 7. 端口转发

服务器上跑的服务监听 `127.0.0.1:<端口>` 时，在「端口」面板转发到本地，浏览器访问 `http://127.0.0.1:<端口>` 即可。也可以在设置里预置：

```json
"remote.SSH.defaultForwardedPorts": [
  { "localPort": 3000, "remotePort": 3000 }
]
```

看到这个就算成：本地浏览器能打开服务器上的服务，且服务器端口没有对外暴露。

### 8. 容器与 WSL（可选）

同一套扩展还有 Dev Containers 与 WSL 两种模式：前者在容器里开发，后者在 Windows 上接 Linux 子系统。实验室服务器场景用 Remote-SSH 就够，另两种按需。

看到这个就算成：能说出自己该用哪种模式，以及为什么。

## 四、做完怎么确认

1. 编辑器界面为中文，版本可在命令行查到。
2. 能用别名登录服务器，并在编辑器里连上。
3. 服务器上的文件可以直接编辑，改动即时保存。
4. 服务器上的服务能通过本地端口访问。

## 五、卡住了怎么排查

| 症状 | 多半是 | 先验证 | 处理 |
| --- | --- | --- | --- |
| 连接超时 | 不在 tailnet 内，或端口不通 | `$ ssh lab` 是否成功 | 先修 SSH 与组网；见 [SSH](../SSH.md) |
| 一直提示装 Server | 服务器访问不了外网 | 服务器上 `$ curl -I https://update.code.visualstudio.com` | 配代理；或按官方文档离线安装 |
| 登录反复要密码 | 没配密钥 | `$ ssh -v lab` 看认证方式 | 配 `~/.ssh/config` 与免密登录 |
| 端口转发后打不开 | 服务只监听回环但端口填错 | 服务器 `$ ss -tlnp` | 核对端口；重开转发 |
| 中文界面没生效 | 语言包未安装完成 | 命令面板搜 Display Language | 重装中文语言包并重启 |
| 连接后文件树是空的 | 打开了错目录 | 左侧路径确认 | `Open Folder` 重选目录 |
| 连远程后本地扩展失效 | 部分扩展只在本地或只在远端生效 | 扩展面板看安装位置 | 在远程窗口里重装需要的扩展 |

## 六、为什么这样能成

**Remote-SSH 只把界面留在本地。** 编辑器在本机渲染，文件读写、终端、调试进程都在服务器上跑，所以大项目也不会把本地机器拖慢。

**SSH 配置被编辑器复用。** Remote-SSH 读的就是 `~/.ssh/config`，终端与编辑器共用一份别名，改一处两边都生效。

**端口转发是在隧道里开的口子。** 转发只在本机与服务器之间建立，服务器端口不需要对外开放，也不用改防火墙。

## 七、边界与替代

- **不做完整远程桌面**：只需要终端与编辑器时用 SSH，不必上 VNC。
- **容器与 WSL 另有场景**：本页只到 Remote-SSH，容器化开发见[容器与编排](../容器与编排.md)。
- **先修好网络再装插件**：连不上服务器时反复重装扩展没有意义。
- **别在服务器上装图形界面**：远程开发的目的就是省掉这一层。
