# VS Code 设置与插件

## 一、这页讲什么

默认设置对新手够用，但实验室的机器、远程环境、语言各不相同：换台机器要重配一遍最费时间。设置写进 JSON 才能带着走，插件只留真正在用的才不拖慢启动。

读完能做到：改用户级与项目级设置；把配置同步到另一台机器；判断一个插件是否值得装、装错后怎么退回。

## 三、动手做

### 1. 认清两级设置

| 级别 | 位置 | 作用范围 |
| --- | --- | --- |
| 用户级 | 本机用户目录下的 `settings.json` | 这台机器上的所有项目 |
| 项目级 | 项目里的 `.vscode/settings.json` | 只对该项目生效，随仓库走 |

命令面板 → `Preferences: Open User Settings (JSON)` 打开用户级；项目里直接编辑 `.vscode/settings.json`。

看到这个就算成：两个文件都能打开，里面的内容互不影响。

### 2. 写几条常用设置

```json
{
  "editor.tabSize": 2,
  "editor.formatOnSave": true,
  "files.autoSave": "onFocusChange",
  "files.trimTrailingWhitespace": true,
  "editor.rulers": [100]
}
```

看到这个就算成：保存后新开文件的行宽、缩进、自动保存按设置生效。

### 3. 项目级设置只放项目相关的项

编解码、格式化器、路径别名这类与仓库绑定的设置放 `.vscode/settings.json`，随仓库提交；个人偏好留在用户级。

看到这个就算成：`.vscode/settings.json` 里没有只与自己习惯相关的条目。

### 4. 打开设置同步

点左下角账户图标 → `Turn on Settings Sync`，选择要同步的内容（设置、键位、扩展、代码片段）。同步走 GitHub 或 Microsoft 账户。

看到这个就算成：另一台机器登录同一账户后设置自动出现。

### 5. 插件按需装

先装三类：语言支持（如 Python、C/C++）、远程开发（Remote - SSH）、中文语言包。其余按遇到的具体问题再装。

| 场景 | 装什么 |
| --- | --- |
| 写 Python | Python（含 Pylance） |
| 连服务器 | Remote - SSH |
| 看 Git 差异 | 内置源代码管理面板够用，需要逐行 blame 再装 GitLens |
| 写 Markdown | Markdown All in One 可选，本仓库用命令行 lint 更可靠 |
| 核对拼写 | Code Spell Checker |

看到这个就算成：扩展面板里没有自己说不出去用途的扩展。

### 6. 插件冲突与退回

装完变慢或功能异常时，用命令面板的 `Extensions: Show Running Extensions` 看谁在耗时间；也可以禁用一半扩展二分定位，或启动时加 `--disable-extensions` 验证是否为插件引起。

看到这个就算成：能指出最近一次变慢对应哪个扩展，并会禁用与恢复。

## 四、做完怎么确认

1. 用户级与项目级设置都能打开，职责划分清楚。
2. 几条常用设置在保存后立即生效。
3. 设置同步已开启，换机器能带回配置。
4. 装过的每个扩展都能说出用途。

## 五、卡住了怎么排查

| 症状 | 多半是 | 先验证 | 处理 |
| --- | --- | --- | --- |
| 改了设置没生效 | 改在项目级但被用户级覆盖，或语法错 | 看 `settings.json` 是否有红色波浪线 | 修正 JSON；确认两级的优先级 |
| 设置同步后本机错乱 | 同步了不同系统的项 | 对比两台机器的设置 | 关闭个别项的同步 |
| 装完插件变慢 | 扩展占资源或冲突 | `Extensions: Show Running Extensions` | 禁用其中一个，二分定位 |
| 格式化保存时把代码改乱 | 默认格式化器选错 | 右下角看当前格式化器 | 指定语言对应的格式化器 |
| 远程窗口里设置不生效 | 远程窗口有自己的设置层 | 命令面板打开远程设置 | 在远程层重设，或改项目级 |
| 扩展装到本地但远程用不到 | 扩展分本地与远程两侧 | 扩展面板标注 | 在远程窗口里再装一次 |

## 六、为什么这样能成

**设置是分层的。** 默认 → 用户级 → 项目级 → 语言级，后一层覆盖前一层，所以项目级只写与仓库相关的差异即可。

**`.vscode/` 随仓库同步。** 项目级设置进 Git 后，任何人打开这个仓库都得到同一套行为，不用口头交代。

**扩展分两侧运行。** 远程开发时扩展装在服务器侧，本地装的不一定在远程窗口生效，这也是「装了没用」最常见的来源。

## 七、边界与替代

- **不把个人偏好塞进仓库**：项目级设置一旦提交，所有人的界面都跟着变。
- **不追求插件数量**：每个扩展都参与启动与文件监听。
- **不手改扩展目录**：禁用与卸载走扩展面板。
- **团队格式化规则另有出处**：代码风格以仓库的 lint 配置为准，编辑器设置只是配合。
