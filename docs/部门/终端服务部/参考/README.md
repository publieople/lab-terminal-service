# 参考

**什么时候看这一节**：要动手做某件事，但记不清命令、参数、顺序；或者想确认"我们部门对这件事的规范做法是什么"。

## 一、这一节放什么

**一门技术、一个主题一页**，没有学习顺序，按需查。判断标准很简单：

- 需要**按顺序学**的 → 放[学习](../学习/README.md)
- 需要**用到时查一下**的 → 放这里
- 有版本差异、必须写清适用范围的 → 放这里，并在 front-matter 里写 `适用版本`

每一页按「是什么 / 什么时候用 / 怎么做 / 常见问题 / 相关」五节写。**同一件事的正文只写一处**：学习线要讲它，就链过来，不要复制一遍。

## 二、推荐（建议使用的软件或技术）

这一节回答的是"我该装什么、该用什么"：**推荐级别**分三档——`必装`（不装直接影响干活）、`建议`（装了明显省时间，但原来的办法也能做）、`可选`（看个人习惯）。索引表里的一句话前面会带上级别。

每篇推荐都要写清：什么场景用、为什么是它（含被比下去的同类）、怎么开始、代价与坑、什么情况别用、最后核实时间。软件名写在 `tags` 里，标题写场景。

## 四、怎么用这一节

- 页面标题用你会搜的词（"反向代理"而不是内部代号），搜不到就先看上面的表。
- 术语第一次出现时带上常见同义词，例如「终端（Terminal、命令行、shell）」——站点搜索按文字匹配，同义词只能靠正文写出来。
- 页面里的命令都可以直接复制。执行前先确认 front-matter 的 `适用版本` 和正文里写的"在什么权限下执行"。
