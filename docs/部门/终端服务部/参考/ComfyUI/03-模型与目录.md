# ComfyUI 模型与目录

## 一、这页讲什么

ComfyUI 装好后是空的，模型要自己下、自己放。这一页解决三件事：每类模型放进 `ComfyUI/models/` 下的哪个子目录；手动拷进去之后为什么列表里看不到；多份 ComfyUI 怎么共用同一个模型盘。

读完能做到：把 checkpoint、LoRA、VAE 放对位置并在下拉框里选到；用 `extra_model_paths.yaml` 把模型目录指到别的盘；判断一个模型文件该归哪一类。

## 二、开始之前

| 项 | 内容 |
| --- | --- |
| 版本与日期 | ComfyUI 2026-10 最新版；2026-10-21 核实 |
| 预计耗时 | 15 分钟，不含下载模型的时间 |
| 前置 | [01-部署](01-部署.md)已完成，服务能启动 |
| 风险级别 | 低：只往模型目录里放文件，注意别把磁盘写满 |

模型不在安装包里，要另外下载。单个生成模型常有好几个 GB，放之前先确认磁盘剩余空间。

## 三、动手做

### 1. 认清模型目录

```text
ComfyUI/
└── models/
    ├── checkpoints/        整包模型，一次加载一整套
    ├── loras/              风格、角色、概念的小补丁
    ├── vae/                解码用，有些整包模型不带
    ├── controlnet/         按边缘、深度、姿态做额外引导
    ├── clip/               文本编码器
    ├── clip_vision/        图像编码器
    ├── embeddings/         文本反演
    └── upscale_models/     放大模型
```

看到这个就算成：能说出 checkpoint 与 LoRA 分别放在哪个子目录。以实际安装目录里的子文件夹为准，不同版本会多出几个。

### 2. 按用途判断放哪

| 文件特征 | 放到 | 说明 |
| --- | --- | --- |
| 单个 `.safetensors`，2 GB 以上，能独立出图 | `checkpoints/` | 整包模型，含主模型与通常的 VAE |
| 几百 MB，要在整包模型之外叠加使用 | `loras/` | LoRA，靠提示词或节点权重生效 |
| 300 MB 上下，节点里单独加载 | `vae/` | 有些模型把 VAE 拆出来发布 |
| 按姿态、深度、边缘做约束 | `controlnet/` | 常见前缀 control_、t2i_adapter |
| 负责把图放大 | `upscale_models/` | 4x-UltraSharp 一类 |

看到这个就算成：拿到一个文件，能根据体积和用途说出该放的目录，而不是挨个目录试。

### 3. 拷贝后刷新列表

手动拷文件时服务还开着，模型列表不会自动更新。

```text
右侧面板 → 模型下拉框旁的刷新按钮
```

看到这个就算成：点开「加载模型」节点，下拉框里出现刚放进去的文件名。刷新不出来就重启服务，重启一定会重新扫描目录。

**放错目录不会报错，只是列表里看不见**——这是最常见的坑。

### 4. 让多份 ComfyUI 共用模型盘

多份安装各下一套模型，磁盘和带宽都浪费。用配置文件把搜索路径指到共享目录：

```yaml
# ComfyUI/extra_model_paths.yaml
shared_models:
    base_path: D:/models
    checkpoints: checkpoints
    loras: loras
    vae: vae
```

根目录里有现成的示例文件 `extra_model_paths.yaml.example`，复制一份改名即可；`base_path` 填共享盘的根，下面每行写该类型对应的相对目录。

看到这个就算成：重启后下拉框里同时有本机目录和共享目录里的模型。放进去的文件两边都能选到。

### 5. 腾空间

```bash
$ du -sh models/* | sort -h | tail -5
4.1G    models/checkpoints
1.2G    models/loras
```

界面里没有卸载按钮，删文件就是卸载。删之前确认没有工作流还在引用这个文件。

看到这个就算成：能按目录说清空间被哪类模型占着。

## 四、做完怎么确认

1. 各类模型在下拉框里能看到，能选中并成功加载。
2. `extra_model_paths.yaml` 生效，共享目录里的模型出现在列表里。
3. 磁盘还有余量，没有因为放模型把系统盘写满。

## 五、卡住了怎么排查

| 症状 | 多半是 | 先验证 | 处理 |
| --- | --- | --- | --- |
| 文件放进去了，下拉框里没有 | 放错子目录，或没刷新 | 对照本页第 1 步的目录树、点刷新 | 移到对的目录；重启服务 |
| 加载模型报架构不匹配 | 模型与当前加载器不是一类 | 看报错里的模型名与节点类型 | 换对应加载器；确认模型不是别的框架专用格式 |
| `extra_model_paths.yaml` 不生效 | 文件不在根目录，或缩进写错 | 看启动时有没有报 YAML 解析错误 | 放到 `ComfyUI/` 根下；按示例文件对齐缩进 |
| 提示模型下载失败 | 网络到下载源不稳 | 浏览器直接下同一个文件 | 先下好再拷进去，别在界面里等 |
| 加载两个模型就 OOM | 显存同时装不下 | `$ nvidia-smi` 看占用 | 换更小的模型或量化版，见[性能与显存](06-性能与显存.md) |
| 磁盘被写满 | 模型、输出图、日志堆在一起 | `$ df -h` 与 `$ du -sh *` | 清旧模型与输出；模型盘单独挂一块 |

## 六、为什么这样能成

**目录就是注册表。** ComfyUI 启动时扫描 `models/` 下的各个子目录，把找到的文件按目录归类进对应的下拉框。文件放在哪个子目录，界面上就归到哪一类下拉框里。

**手动拷贝不会触发扫描。** 服务只在启动时和手动刷新时读目录，运行中往里面丢文件不会被发现。

**配置文件是搜索路径的合并。** `extra_model_paths.yaml` 只是在默认目录之外再加几个候选位置，选到哪个文件仍由下拉框里的名字决定。多份安装指向同一个共享目录时，各读各的，文件本身是只读使用的。

## 七、边界与替代

- **不管模型从哪来**：来源合规、授权范围自行确认，本页只讲放哪。
- **不教模型怎么选**：哪个模型适合什么风格属于出图经验，写在[经验](../../经验/README.md)。
- **不提供下载代理**：实验室网络下载大文件的做法在内部台账，不写进公开页。
- **一台机器别装多套**：多人共用走统一入口，模型盘共享也要统一目录，否则同一个文件会被下好几份。
