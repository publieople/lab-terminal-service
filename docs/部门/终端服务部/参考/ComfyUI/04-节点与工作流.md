# ComfyUI 节点与工作流

## 一、这页讲什么

ComfyUI 的界面就是一张节点图。这一页讲清三件事：一个节点由哪几块组成；连线为什么有颜色、什么情况下连不上；工作流怎么存下来并交给别人跑。

读完能做到：看懂别人给的工作流每步在干什么；改一个参数只影响对应环节；把工作流存成文件、导出成接口能用的 JSON。

## 三、动手做

### 1. 认出一个节点的四个部分

| 位置 | 是什么 | 例子 |
| --- | --- | --- |
| 标题栏 | 节点名，可能带显示名 | `Load Checkpoint`、`KSampler` |
| 左侧输入槽 | 接收上游数据 | `model`、`positive`、`latent_image` |
| 右侧输出槽 | 把结果交给下游 | `MODEL`、`CONDITIONING`、`LATENT` |
| 节点内部 | 参数控件（widget） | 采样步数、CFG、种子、分辨率 |

看到这个就算成：能在任意一个节点上指出输入、输出、参数三个位置。槽的颜色对应数据类型，同色才能连。

### 2. 加一个节点

在画布空白处双击，输入节点名搜索；或右键用菜单逐级找。加出来的节点是孤立状态，需要手动连线。

看到这个就算成：新节点出现在画布上，但没有任何连线——孤立节点不参与执行。

### 3. 连线与拆线

从一个节点的输出槽拖到另一个节点的输入槽，颜色一致才连得上。断开就拖住线头甩到空白处。

看到这个就算成：改动一行连线后，执行结果会变；连不上的两条线，界面直接不给落点。

### 4. 存工作流

顶栏或左侧「工作流」里保存，得到一份工作流记录，重启界面后还在列表里。工作流只记录节点和连线，**不含模型文件**。

看到这个就算成：换个入口重新打开这份工作流，节点、连线、参数都还原。

### 5. 把工作流交给别人

两种方式：

- 存成图片：出图时工作流会写进 PNG 的元数据，对方把图拖进画布就能还原；
- 存成文件：导出工作流 JSON，对方用「打开工作流」载入。

**导出的默认格式是前端格式，不能直接喂给接口**。要让程序调用，得在导出菜单里选 API 格式（`Save (API Format)`），另存一份。

看到这个就算成：把自己导出的文件在另一台机器上打开，节点齐全。

### 6. 分组与整理

选中多个节点后右键成组（Group），给组起名并上色。复杂工作流按「加载 → 条件 → 采样 → 解码 → 保存」分组，排错时一眼能定位到段。

看到这个就算成：整张图能被折叠成三到五个组，每组职责一句话能说清。

## 四、做完怎么确认

1. 能说清一张模板工作流里每个节点负责哪一步。
2. 改一个采样参数，只有对应环节的结果变化。
3. 工作流能保存、能重新载入。
4. 另存了 API 格式 JSON，节点结构完整。

## 五、卡住了怎么排查

| 症状 | 多半是 | 先验证 | 处理 |
| --- | --- | --- | --- |
| 节点边框变红 | 必填输入没接，或模型没加载 | 看节点上缺的是哪个槽、右侧面板的报错 | 补连线；把模型选上 |
| 两条线连不上 | 数据类型不同 | 看两个槽的颜色与名字 | 中间加转换节点（如 VAE 解码） |
| 别人的工作流跑不动 | 缺自定义节点或缺模型 | 看提示缺哪个节点类 / 哪个模型文件 | 装节点、放模型，见[常用第三方节点](05-常用第三方节点.md) |
| 关闭后工作流丢了 | 没保存到工作流列表，只改了画布 | 打开「工作流」列表找 | 改完先保存；重要工作流另存文件 |
| 执行顺序看不懂 | 节点图不是从上到下执行的 | 顺着连线找实际依赖 | 以连线为准，别按节点位置猜顺序 |
| 接口调用返回 400 | 提交的是前端格式工作流 | 看返回里的 `node_errors` | 重新导出 API 格式，见[生态与替代](08-生态与替代.md) |

## 六、为什么这样能成

**节点图是有向无环的数据流。** 每个节点是一步运算，连线表示上一步的输出交给下一步。执行顺序由依赖决定，节点在画布上的位置不参与计算。

**同色才能连，是类型检查。** 槽的颜色对应数据类型，连错类型在编辑阶段就被拦下，不必等到执行才报错。

**工作流是结构，不是结果。** 存下来的只有节点、连线和参数，模型权重在模型目录里。换机器时工作流照搬，模型要另外准备。

**结果会被缓存。** 同样的输入与参数再次执行时，ComfyUI 可以复用上一次的结果；改动的节点之后才重新算。这也是「只改一处，只有一处变」的原因。

## 七、边界与替代

- **不写自定义节点**：自己开发节点看官方开发者文档，不在本页范围。
- **不做工作流美学**：节点怎么摆、怎么分组看个人习惯，唯一的标准是别人能看懂。
- **别拿工作流当配置管理**：多套流程要版本化时存到 git 仓库，别只放在界面里。
- **复杂工作流先跑通再加**：一次只加一个节点，否则出不来图时分不清是谁的问题。
