# ComfyUI 常用第三方节点

## 一、这页讲什么

ComfyUI 核心节点只覆盖常见流程，很多能力要靠第三方节点包。这一页讲清：怎么开启内置的 Manager；怎么装、更新、禁用节点；节点装上却没出现时从哪里查；装坏了怎么退回。

读完能做到：在界面上装好一个节点包并跑通；用启动参数排除节点导致的问题；判断一个新出的节点包值不值得装。

## 三、动手做

### 1. 开启内置 Manager

新版 Manager 随 ComfyUI 核心提供，但要显式开启。Windows 便携版在解压目录里执行：

```bat
.\python_embeded\python.exe -m pip install -r ComfyUI\manager_requirements.txt
```

然后把 `--enable-manager` 加到启动参数（便携版改 `run_nvidia_gpu.bat`）。已经装了旧版 Manager 自定义节点的，界面里会提示迁移。

看到这个就算成：界面里出现 Manager 入口，能看到已安装节点列表。`--disable-manager-ui` 可以只关界面、保留后台能力。

### 2. 设置安全级别

Manager 的安全级别决定能装什么来源的节点包：

| 级别 | 含义 | 适用范围 |
| --- | --- | --- |
| Strict | 只装注册表里通过审核的包 | 对外暴露的机器 |
| Standard | 默认，注册表优先 | 实验室内部机器 |
| Relaxed | 允许更多来源 | 自己机器、临时试验 |
| Permissive | 基本不设限 | 不建议 |

网络模式（Public / Private / Offline）决定 Manager 怎么连节点仓库。机器不能直连外网时选 Offline，改用手动放包。

看到这个就算成：能在设置里说出当前用的是哪一级，并知道对外暴露的机器不能用 Relaxed。

### 3. 装一个节点包

在 Manager 的节点列表里搜索，选中后安装。安装会做两件事：下载包到 `ComfyUI/custom_nodes/`，按包里的依赖清单装 Python 包。

看到这个就算成：安装完成后重启，节点出现在右键菜单和双击搜索里。

### 4. 手动装与手动删

节点包本质就是 `custom_nodes/` 下的一个目录：

```bash
$ ls custom_nodes/
ComfyUI-Manager  ComfyUI-Impact-Pack  was-node-suite-comfyui
```

手动装就把目录拷进去，依赖用同一套 Python 环境装：

```bash
.\python_embeded\python.exe -m pip install -r custom_nodes\<包名>\requirements.txt
```

看到这个就算成：目录里有包，重启后节点出现。删节点就是删目录，删完重启。

### 5. 更新与回退

在 Manager 里更新已装节点。更新前先把工作流存好，节点升级可能改节点名或参数名。

回退有两种：Manager 里选旧版本；或者进包目录用 git 退回上一个提交（包通常就是 git 仓库）。

看到这个就算成：更新后跑通原来的工作流；出问题时能退回上一个可用版本。

### 6. 用启动参数排除节点

怀疑是节点导致启动失败或出图报错时，先整体关掉：

```bat
.\python_embeded\python.exe -s ComfyUI\main.py --windows-standalone-build --disable-all-custom-nodes
```

看到这个就算成：加上参数能正常启动、能出图，说明问题出在某个节点包，再逐个开回来定位。

### 7. 加详细日志

节点加载失败的完整报错在控制台里，默认可能被省略。需要细节时提高日志级别：

```bat
.\python_embeded\python.exe -s ComfyUI\main.py --windows-standalone-build --verbose DEBUG
```

看到这个就算成：控制台打印出每个节点包的导入过程，报错能看到具体模块名。

## 四、做完怎么确认

1. Manager 能打开，已装节点列表正常显示。
2. 新装的节点包在节点菜单里能找到并跑通一个流程。
3. `--disable-all-custom-nodes` 下能正常启动。
4. 知道当前安全级别与网络模式。

## 五、卡住了怎么排查

| 症状 | 多半是 | 先验证 | 处理 |
| --- | --- | --- | --- |
| 启动时报 `ModuleNotFoundError` | 节点包依赖没装全，或装到了别的 Python 环境 | 看报错里的模块名与包的 `requirements.txt` | 用启动 ComfyUI 的那个 Python 装依赖；装不上的包先删掉 |
| 装了节点但菜单里没有 | 没重启，或导入时静默失败 | 重启；看控制台加载日志 | 加 `--verbose DEBUG` 找导入错误 |
| 出图时报某个节点未知 | 工作流引用的节点没装 | 看报错里的节点类名 | 装对应节点包；或换成核心等价节点 |
| Manager 打不开 | 没用 `--enable-manager`，或包没装 | 看启动参数与控制台 | 按第 1 步装依赖并加参数 |
| 更新后原来的工作流报错 | 节点改名、参数改结构 | 对比节点列表与旧工作流 | 回退版本，或按新版重连 |
| 装完 ComfyUI 起不来 | 节点包与当前版本不兼容 | 加 `--disable-all-custom-nodes` 试启动 | 逐个禁用排除；必要时删掉可疑目录 |

## 六、为什么这样能成

**节点包就是目录里的 Python 包。** 启动时扫描 `custom_nodes/`，每个子目录被当作模块导入，导入成功就注册节点。没有单独的注册中心。

**依赖装在同一个环境里。** 节点包声明的依赖由启动 ComfyUI 的那个 Python 解释器加载，用错解释器会出现「装了但导入失败」。

**完整性优先于新。** 安全级别与网络模式限制的是「能装什么来源」；在共享机器上，一个来路不明的节点包等同于让陌生代码在这台机器上跑。

## 七、边界与替代

- **不校验节点质量**：能用不等于值得用，核心节点能做的优先用核心。
- **不重复造轮子**：装之前先看官方模板与核心节点有没有等价能力。
- **共享机器别乱装**：多人共用的实例加节点包前先在群里说一声，装坏了影响所有人。
- **不确定来源就别装**：来路不明的节点包会读到模型、输出目录乃至环境变量。
