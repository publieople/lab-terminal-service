# Git 分支不敢动手，先用可视化练习走一遍

**什么时候点进来**：会 `git add`、`git commit`、`git push`，但一碰到分支、合并、rebase 就心虚；或者刚把仓库改乱过，不敢再动。

## 一、什么场景用

- 只会「提交、推送」这两步，协作时看不懂 PR 里的分支关系。
- 想搞清 `merge` 和 `rebase` 到底差在哪，又不希望在真实仓库上试错。
- 要给别人讲分支图，但自己脑子里没有那张图。

## 二、为什么是它

- **可视化**：每一步操作后，提交图会实时重画，分支、HEAD、标签在哪一目了然。
- **安全**：沙盒里的仓库是假的，`reset`、`revert` 随便用，弄乱了重开一关即可。
- **按关卡推进**：从「基础篇」到「高级篇」，每关只引入一两个新命令，不会一上来就 stack。

为什么没选别的：

- **Pro Git 书**：最权威，但纯文字描述分支变化，需要自己在脑子里画图，入门阶段效率低。
- **文字教程（廖雪峰等）**：讲得清楚，仍然是「读」，缺少手感和即时反馈。
- **直接在部门仓库练**：怕弄坏、怕被 review 打回，练习成本太高。

它只解决「分支怎么动」这一件事，协作流程（fork、PR、review）仍要看仓库的规范文档。

## 三、怎么开始

- 中文入口：<https://learngitbranching.js.org/?locale=zh_CN>
- 顺序：**主要 → 基础篇**（commit、branch、checkout、merge、rebase、HEAD 移动）→ **高级篇**（相对引用、`reset`、`revert`、`cherry-pick`、交互式 rebase）。
- 每关先自己敲，卡住再看提示；「查看答案」留在最后。
- 练完到沙盒（Sandbox）里把部门日常流程走一遍：`git switch -c 分支名` → 改文件 → `commit` → `push` → 开 PR。

## 四、代价与坑

- **关卡用最少的命令集**，和真实仓库有差距：远端、hooks、冲突解决、合并策略都没有覆盖。
- **练完不用会忘**。建议练完一周内，在真实仓库开一个只改文档的分支，走一遍完整流程。
- **界面语言可切**，中英文命令一致，术语按英文记更好查资料。

## 五、什么情况别用

- 要学团队协作流程（谁能合、怎么 review、分支怎么命名）：看仓库根的 `CONTRIBUTING.md` 与 `docs/规范/` 下的《知识库规范》；这两处属于仓库规范、不属本章，这里只以文字提及。
- 要查具体命令的参数：去[终端与命令行](../学习/02-终端环境/01-终端与命令行.md)。
- 已经能熟练解决冲突、用过 rebase：这页对你的价值不大，去写一篇经验更好。
