# 终端与命令

## 第一部分：终端基础概念

### 1. 什么是终端/命令行

终端（Terminal）是一个允许用户与计算机操作系统交互的程序窗口。命令行界面（CLI，Command Line Interface）是通过输入文本命令来执行操作的交互方式。

- **CLI（命令行）**：键盘输入指令。批量自动化、占用资源少，远程管理服务器通常只能用这个。
- **GUI（图形界面）**：点击图标操作。直观、上手快，但批量处理文件与远程管理时效率低。

### 2. 不同操作系统的终端环境

这是新手最容易混淆的地方，**不同系统的命令语法并不完全通用**。

**Windows**：

- **PowerShell (推荐)**：现代 Windows 的默认终端，功能强大。它通过“别名”兼容了部分 Linux 命令（如 `ls`, `cd`, `mv`），但**参数（Flags）通常不兼容**。
- **CMD (命令提示符)**：老旧的 DOS 风格终端，功能较弱，不建议作为主要学习对象。
- **WSL (Windows Subsystem for Linux)**：在 Windows 里运行真正的 Linux 内核。如果你想在 Windows 上完美体验 Linux 命令，这是最佳选择。
- **Git Bash**：安装 Git 后自带的模拟终端，支持大多数 Linux 基础命令。

**macOS / Linux**：

- **Shell (Bash/Zsh)**：macOS 和 Linux 原生使用类 Unix Shell，命令通用性极高（macOS 默认使用 Zsh，与 Linux 的 Bash 高度兼容）。

**其他 Shell**：

- **Fish**：现代 shell，开箱即用，适合新手，但不兼容 bash 语法（可装插件解决）。

## 第二部分：基础命令操作

> **⚠️ 核心提示**：以下命令若无特殊标注，表示在 Linux/macOS 和 Windows PowerShell 中**基础用法**通用。涉及参数（如 `-r`）差异时会分开列出。

### 3. 文件与目录操作

- **`cd`**：`cd path/to/dir` 进入目录，`cd ..` 返回上一级，`cd ~` 回到用户主目录。
- **`ls`**：`ls -l`（详细列表）、`ls -a`（含隐藏文件）；PowerShell 的 `ls` 是 `Get-ChildItem` 的别名，不认 `-l`、`-a` 这种参数写法；CMD 里用 `dir`。
- **`rm`（高危）**：Linux/macOS 用 `rm -rf dir_name` 强制删除目录及其内容，**极为危险，慎用**；PowerShell 写 `rm dir_name -Recurse -Force`，直接敲 `rm -rf` 会报错。

`pwd`、`mkdir`、`cp`、`mv` 的跨系统写法见文末附录表。

### 4. 文件查看与编辑

- **`cat`**：`cat filename.txt` 输出文件内容（PowerShell 里是 `Get-Content` 的别名）。
- **`tail`**：查日志最常用 `tail -f log.txt` 实时跟踪；PowerShell 里对应 `gc log.txt -Wait`。
- **简单文本编辑器**：Linux/macOS 一般预装 `nano`（新手推荐）或 `vim`。
- **Windows 侧编辑器**：`notepad file.txt` 开记事本；装了 Git 或 WSL 才有 `vim`/`nano`；VS Code 用 `code file.txt`。

`head`、`gc -Head` 等见文末附录表。

### 5. 系统信息查看

**`ps` - 查看进程**：

- **Linux/macOS**: `ps aux` (查看所有详细进程)
- **Windows (PowerShell)**: `ps` (显示当前进程对象，不显示 CPU% 等详细历史数据，需配合 `Get-Process`)

**`top` - 资源监控**：

- **Linux/macOS**: `top` 或 `htop` (推荐安装 htop，界面更友好)
- **Windows**: 输入 `taskmgr` 打开任务管理器，或用 `tasklist` 列出进程。

## 第三部分：进阶命令操作

### 6. 管道与重定向

**`>` 和 `>>` - 重定向 (通用)**：

- `echo "Hello" > file.txt` (覆盖写入)
- `echo "World" >> file.txt` (追加写入)

**`|` - 管道 (通用概念)**：

- 将前一个命令的输出，作为后一个命令的输入。
- **区别**：Linux 传递的是**文本流**；PowerShell 传递的是**对象**。
- 例 (Linux): `cat file.txt | grep "error"`
- 例 (PowerShell): `cat file.txt | sls "error"`

### 7. 搜索与过滤 (关键差异点)

- **查文件内容**：Linux/macOS 用 `grep "关键词" filename`；PowerShell 用 `sls "关键词" filename`（`sls` 是 `Select-String` 的别名）；CMD 用 `findstr "关键词" filename`。
- **查文件位置**：Linux/macOS 用 `find /path -name "*.txt"`；PowerShell 用 `gci -Recurse -Filter "*.txt"`（`gci` 是 `Get-ChildItem` 的别名）。
- **⚠️ 避坑**：在 Windows 运行 `find`，调用的是一个古老的文本查找工具，并不是用来找文件的。

### 8. 权限管理

- **Linux/macOS**: `chmod +x script.sh` (添加执行权限)
- **Windows**: 权限管理体系不同 (ACL)，通常使用 `icacls`，但大多数日常开发不需要频繁修改文件权限。

### 9. 快捷键 (提效神器)

Tab 自动补全与 ↑ / ↓ 翻历史最常用，完整快捷键表见[终端环境与配置](终端环境与配置.md)五、5.4。

### 10. 环境变量

PATH 的作用见[Windows 基本操作](../学习/Windows基本操作.md)五、5.3。两个系统里查看与临时修改 PATH 的命令：

- **查看**：Linux/macOS 用 `echo $PATH`，PowerShell 用 `$env:PATH`。
- **临时修改**：Linux/macOS 用 `export PATH=$PATH:/new/dir`，PowerShell 用 `$env:PATH += ";C:\new\dir"`。

## 第五部分：使用 AI 获取命令行帮助

### 11. AI 与终端交互的高效方法

**关键原则：必须告诉 AI 你的操作系统！**

因为 Linux Bash 和 Windows PowerShell 差异很大，如果不指定系统，AI 可能会给出无法执行的命令。

**🔴 错误的提问：**

> “怎么查看占用端口的进程？”（AI 可能给出 Linux 的 `lsof`，在 Windows 上无法执行）

**🟢 正确的提问：**

> “我在 Windows 11 的 PowerShell 中，想查看哪个进程占用了 8080 端口，请给出命令。”

**验证 AI 给的命令：**

- 先弄懂命令里每个部分的作用，再确认路径和影响范围；
- 删除、格式化这类破坏性命令，先在测试环境验证；
- 不确定的参数用 `--help` 或 `man` 查说明。

### 12. 现代 AI 命令行工具

利用 AI 工具可以将自然语言直接转换为命令。

- **[Claude Code](https://github.com/anthropics/claude-code)**: Anthropic 官方工具，理解能力极强，适合解释复杂脚本。
- **[iFlow CLI](https://iflow.cn/)**: 国产免费 AI 命令行工具，适合自动化任务流。
- **[GitHub Copilot CLI](https://github.com/features/copilot/cli)**: 专门用于将 "How do I..." 转换为命令的工具。

### 13. AI 辅助实战案例

- **文件操作**：提问“我在 Linux 上，想把当前目录下所有 .txt 文件移动到 backup 目录（如果不存在则创建）”，AI 应给出 `mkdir -p backup && mv *.txt backup/`。
- **系统监控**：提问“我在 Windows 11 PowerShell 上，想查看占用内存最多的 3 个进程”，AI 应给出 `Get-Process | Sort-Object -Property WorkingSet -Descending | Select-Object -First 3 Id,Name,WorkingSet`。
- **文本处理**：提问“我在 macOS 上，想在文件中查找包含 error 的所有行并保存到新文件”，AI 应给出 `grep "error" input.txt > errors.txt`。

### 15. 故障排查常见报错

1. **`command not found`** (Linux) / **`无法将“xxx”项识别为 cmdlet...`** (Windows)

   - **原因**: 命令拼错了，或者该软件没安装，或者没加到 PATH 环境变量里。

2. **`Permission denied`** / **`拒绝访问`**

   - **原因**: 权限不足。
   - **解决**: Linux 加 `sudo`；Windows 以"管理员身份"运行终端。

3. **`Path not found`**

   路径里有空格没加引号。正确写法见[文件与路径](../学习/01-Windows基础/01-文件与路径.md)三、3.4。

## 附录：命令速查对照表

| 功能 | Linux / macOS (Bash/Zsh) | Windows (PowerShell) | 关键区别 |
| --- | --- | --- | --- |
| **切换目录** | `cd` | `cd` | 通用 |
| **列出文件** | `ls -la` | `ls` 或 `dir` | PowerShell 不支持 -la 参数 |
| **显示路径** | `pwd` | `pwd` | 通用 |
| **创建目录** | `mkdir -p a/b` | `mkdir a/b` | 通用 |
| **删除文件** | `rm file` | `rm file` | 通用 |
| **删除目录** | `rm -rf dir` | `rm dir -Recurse -Force` | **Flags 完全不同！** |
| **移动/重命名** | `mv` | `mv` | 通用 |
| **复制** | `cp -r` | `cp -Recurse` | 参数不同 |
| **查看内容** | `cat` | `cat` (别名) | 通用 |
| **看前 N 行** | `head -n 5` | `gc -Head 5` | 命令不同 |
| **看末尾/监控** | `tail -f` | `gc -Wait` | 命令不同 |
| **搜索文本** | `grep "text"` | `sls "text"` | **Windows 没有 grep** |
| **查找文件** | `find . -name "*.txt"` | `gci -r -filter "*.txt"` | **Windows 的 find 是另一回事** |
| **清屏** | `clear` | `clear` / `cls` | 通用 |
| **管理员运行** | `sudo 命令` | (无直接命令) | 需右键以管理员打开 PowerShell |
