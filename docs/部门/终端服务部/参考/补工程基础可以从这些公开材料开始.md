# 补工程基础可以从这些公开材料开始

## 一、什么场景用

课堂讲语法与算法，但日常真正卡人的是另一类东西：命令行用不顺、不敢动 Git 历史、服务出问题只会看最后一行日志、正则写不出来只能用 `.*` 硬凑。

这些内容散在公开材料里，没有统一课表。这个页把常用的几份拢在一起，按「最近卡在哪」挑一份读。

适合：刚进部门、想补工程习惯的人；以及已经在做事、但每次遇到同类问题都要重新查的人。

## 二、为什么是它

| 材料 | 讲什么 | 什么时候读 |
| --- | --- | --- |
| [The Missing Semester of Your CS Education](https://missing.csail.mit.edu/)（MIT） | 命令行、Shell 脚本、Git、调试与性能分析 | 想系统补命令行与工具链，**建议第一个读** |
| [Google SRE · Postmortem Culture](https://sre.google/sre-book/postmortem-culture/) | 故障复盘为什么写、怎么写才不变成追责 | 要写第一篇复盘时 |
| [The Twelve-Factor App（中文）](https://12factor.net/zh_cn/) | 配置、依赖、日志、进程模型的基本原则 | 设计一个要长期跑的服务时 |
| [Pro Git（中文）](https://git-scm.com/book/zh/v2) | 版本控制的规范用法，第 2、3、7 章最实用 | 合并冲突、误提交、要回退时 |
| [Julia Evans · A few debugging resources](https://jvns.ca/blog/2019/06/23/a-few-debugging-resources/) | 调试方法论与工具清单，篇幅短 | 觉得自己「调不动」时 |
| [Debugging Rules!](https://www.debuggingrules.com/) | 九条调试规则，站点提供可打印清单 | 想给团队定一条调试纪律时 |
| [Oh Shit, Git!?!（中文）](https://ohshitgit.com/zh) | 提交搞砸之后的救场命令 | 需要立刻救火时 |
| [正则表达式 30 分钟入门教程](https://deerchao.cn/tutorials/regex/regex.htm) | 元字符、分组与断言 | 第一次系统学正则时 |
| [Regex101](https://regex101.com/) | 在线正则调试器：逐段解释、匹配高亮 | 正则写不出来的每次 |
| [Regexper](https://regexper.com/) | 把正则画成流程图 | 正则太长、读不懂自己在写什么时 |

选这些的理由：都能直接在线读、长期有人在维护、并且都能在一次卡点里用上，不需要先读完再动手。

## 三、怎么开始

1. 先想清楚最近一次卡住是什么：是命令行不熟、Git 不敢动、还是排障没有章法。
2. 从上面表里挑对应的一篇，只读与这次卡点相关的一节。
3. 边读边在自己的机器上复现一遍命令。读十篇不留一条，等于没读。
4. 读完把能直接用的一条按[经验](../经验/README.md)的格式写下来：现象、原因、判断规则。

看到这个就算成：能用一句话说出学到的判断规则，并在自己机器上验证过一次。

## 四、代价与坑

- **材料之间会互相矛盾。** 同一件事不同年代写法不同，以能跑通、能验证的为准。
- **英文材料占一半。** Missing Semester 与 Julia Evans 的页面是英文，术语可以查，不必全译。
- **读完容易忘。** 不带着具体问题去读，收藏夹只会越来越长。
- **站点会失效。** 链接核对过状态码，发现打不开直接替换或删掉那一行。

## 五、什么情况别用

- **想学编程语言本身**：语言课在[学习路径](../学习/学习路径.md)，这里不替代。
- **想找某个软件的安装步骤**：安装类见「参考」下的对应页面。
- **打算一次读完**：这些材料适合按卡点取用，通读的收益远低于反复查。
- **需要考核或证书**：这些材料不发证，考核由部门另行安排。
