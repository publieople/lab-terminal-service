# 学习路线

**什么时候看这一页**：刚进部门不知道从哪开始，或者想确认某个方向该按什么顺序学。

这一节只放**有先后顺序**的内容。没有顺序、需要时查一下的东西在[参考](../参考/README.md)那一节；做出来的项目在[项目](../项目/README.md)，踩过的坑在[经验](../经验/README.md)。

## 一、按顺序学

每一章是一个目录，章内按 `01`、`02` 排序，序号就是建议的学习顺序。跨章的前置关系写在章节导览里。

| 章 | 教什么 | 学完能做什么 | 状态 |
| --- | --- | --- | --- |
| `01-Windows基础` | 文件与路径、快捷键与窗口、常用软件 | 能把一台新电脑配成自己顺手的样子，遇到"文件找不到""程序没反应"知道先看哪里 | 🚧 样板章节 |
| `02-终端环境` | 终端宿主、shell、提示符与外观、会话管理 | 能自己搭一套顺手的终端，在两台机器之间用同一套配置 | 🚧 只有导览 |
| `03-Linux基础` | 登录与权限、文件系统、进程与服务、包管理 | 能连上实验室的 Linux 机器，按文档完成一次部署 | 🚧 只有导览 |

后面还会加：容器与编排、网络与远程访问、生成式工作流。顺序没定，等[参考](../参考/README.md)那一节的内容攒够了再拆课。

## 三、怎么用这一节

1. **先看每章的导览页**，那里有本章的课程表和前置要求。
2. **每讲结尾都有验收标准**，写成能动手做出来的动作。做不出来说明没学会，回到正文重做一遍。
3. **遇到卡住的地方**，先在[经验](../经验/README.md)那一节搜现象原文——部门的坑都写成了一坑一篇。
4. 学完想留下记录，按仓库里《知识库规范》「加一页」的步骤写一页，别只留在自己的笔记里。（规范在仓库的 `docs/规范/` 下，正文不链过去——这一章要能整章并入实验室主书，章内不出现指向章外的链接。）
