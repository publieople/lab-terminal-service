# ComfyUI 部署

> ⚠️ **本页是骨架**：§一、§二、§四 已写实，其余小节待补。缺口清单见[待补事实](../待补事实.md) E2。

## 一、技术是什么

**一个用节点图来描述生成式图像工作流的工具**：把"加载模型 → 编码提示词 → 采样 → 解码 → 保存"这些步骤画成一个个连起来的节点，点一次执行整条链路。

它替代的做法是"写一段脚本调库"——脚本的问题是**参数藏在代码里、流程改了要重写、别人的成果没法直接拿来用**。节点图把这些变成可视化且可导出的东西：一张工作流就是一个能直接发给别人的文件。

## 二、为什么使用

- **流程可见**：一张图能看出这条工作流到底做了什么，不需要读代码。
- **可复现**：工作流可以导出成文件，别人导入后跑出同样的结果（前提是模型一致）。
- **可组合**：节点能拼出很复杂的链路（多阶段采样、条件控制、后处理、批量变体）。
- **对非开发者友好**：使用者不需要会写 Python。

### 在什么情况下不值得

| 情况 | 为什么不用 |
| --- | --- |
| 只需要一次性的简单转换（裁剪、格式转换） | 用普通命令行工具更快 |
| 需要稳定的批量生产管线、要接进别的系统 | 节点图的接口不如直接调库稳定；这种场景应考虑把工作流固化成脚本或 API |
| 没有 GPU 的机器 | 能跑但慢到不实用 |

**代价**：ComfyUI 的扩展生态很活跃，但**第三方节点质量参差**，一个坏节点能让整个环境起不来。所以实验室的做法是**把工作流和它依赖的节点版本一起记录**，而不是"装最新版就行"。

## 三、工作原理

> 待补：节点图 → 执行队列 → 模型加载与缓存 → 输出落盘；一次执行的完整数据流。

## 四、使用环境

| 项 | 说明 |
| --- | --- |
| GPU | 必需，见[GPU 与 CUDA 环境](GPU与CUDA环境.md) |
| Python | 版本待补；**不要与系统 Python 混用**，用独立虚拟环境 |
| 框架 | PyTorch（CUDA 版本要与驱动匹配） |
| 模型存放 | 有固定目录结构（检查点 / LoRA / VAE / 文本编码器等各占一个目录），**放错目录的表现是"列表里看不见"而不是报错** |
| 监听地址 | ⚠️ 默认只监听 `127.0.0.1`，别人打不开是设计如此。要让组网内其他设备访问，见[Tailscale 组网](Tailscale组网.md) 的 `serve` 用法，**不要直接把监听地址改成 `0.0.0.0` 暴露到校园网** |
| 端口 | 需在内部库的端口登记表里登记 |
