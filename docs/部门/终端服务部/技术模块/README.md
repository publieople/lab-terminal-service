# 技术模块

**一门技术一篇。**这里回答的是"**怎么用**"——具体的安装、配置、排错步骤，照着做能跑通。

和[基础知识](../基础知识/README.md)的分工：基础知识讲「这是什么、为什么需要」，技术模块讲「怎么装、怎么配、坏了怎么查」。

每篇都按固定八节写（技术是什么 / 为什么使用 / 工作原理 / 使用环境 / 基本使用 / 实际应用 / 常见问题 / 延伸方向）。**固定结构本身就是价值**：找"坏了怎么办"永远在第七节，找"能不能用在我的环境"永远在第四节，不用每次重新翻。

## 阅读顺序建议

第一次接触这套环境的，按这个顺序读三篇就够开始干活：

```text
Linux 服务器运维   →   知道机器在哪、怎么登录、服务怎么起来
        ↓
Tailscale 组网     →   知道自己从哪儿能连到哪儿
        ↓
Agent 平台部署      →   知道自己的任务跑在哪儿、怎么不被断线打断
```

其余模块按需查看，不必通读。

## 新增一个技术模块

```powershell
node scripts/new.mjs 技术模块 docs/部门/终端服务部/技术模块/Ansible批量配置
```

然后：填 front-matter 的 `维护人`、按小节往骨架里填内容、把新文件加进 `nav.片段.yml` 和上表。

**内容质量的最低要求**（四条都要满足）：能理解、能学习、能复现、能延续。其中「能复现」最容易达不到——写完请**自己照着做一遍**，做不到就改，不要指望读者比作者更耐得住。
