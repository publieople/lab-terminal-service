# 学习课程

**这一类回答"一门课怎么上"**：谁来学、要会什么前置知识、学完能做什么、分成哪几个知识模块、配什么练习、最后接到哪个项目上。

## 本类与技术模块的分工

| | 学习课程 | [技术模块](../技术模块/README.md) |
| --- | --- | --- |
| 回答 | 我要按什么顺序学、学到什么程度算会 | 这门技术怎么用 |
| 形态 | 一条路径 + 若干门课 | 一门技术一篇参考 |
| 对读者 | 新人（不知道从哪开始） | 已经知道要找什么的人 |

课程里要讲一门技术的细节时，**链到技术模块，不要抄一遍**。

## 新人上手路径

新成员按下面六步走完，就算完成了入门。

| 步 | 做什么 | 看哪里 | 完成标准 |
| --- | --- | --- | --- |
| ① | 知道这个部门是干什么的、找谁办事 | [部门介绍](../README.md)、[职责与服务目录](../职责与服务目录.md) | 能说出六大职责，知道要服务器该走哪个流程 |
| ② | 知道实验室有哪些机器和服务、怎么连上去 | [技术模块：Tailscale 组网](../技术模块/Tailscale组网.md) | 能把自己的设备接进组网，能 ping 通一台服务器 |
| ③ | 会基本的 Linux 操作与远程登录 | [技术模块：Linux 服务器运维](../技术模块/Linux服务器运维.md)（待补） | 能登录服务器、看服务状态、读日志、找到磁盘占用 |
| ④ | 知道服务是怎么被管起来的 | [技术模块：Agent 平台部署](../技术模块/Agent平台部署.md) | 能说清"会话常驻"和"服务托管"分别解决什么问题 |
| ⑤ | 跟着做一个真实项目 | [项目实践](../项目实践/README.md) | 按复现步骤独立跑通一次 |
| ⑥ | 自己写第一篇文档 | 《文档写入规范》（`docs/规范/文档写入规范.md`，站点「写作规范」页）、仓库根的 `CONTRIBUTING.md` | 提一个通过 CI 的 PR |

> **第 ⑥ 步才算真正入门。**前五步是"能用"，第六步是"能留下东西"——这个部门的价值一半在运行服务，一半在让下一个人不用重新踩一遍。

## 新增一门课程

```powershell
node scripts/new.mjs 学习课程 docs/部门/终端服务部/学习课程/<课程名>
```

模板在 `_templates/课程模板.md`，七节的标题必须逐字保留（`## 一、课程定位` … `## 七、项目衔接`），没有内容的小节写"不适用"并说明原因。

写完把它加进上面的清单，并在仓库根的 `mkdocs.yml`（`nav:` 段）与 `SUMMARY.md` 里各补一行。
