# 经验

**什么时候看这一节**：出现了从没见过的故障，或者刚刚花了几小时排掉一个坑，想知道别人是不是踩过。

## 一、这一节放什么

**一个坑一篇**，放**真实发生过、并且已经查清原因**的问题。

和技术类页面里的「常见问题」分开：

- **参考页的常见问题** = 已知的、有标准答案的现象（"连不上怎么办"）。
- **经验** = 当时不知道怎么办、花了不少时间才查清的问题。价值在**为什么当初没想到**。

## 二、为什么值得写

一个部门最贵的成本，是**同一个问题被不同的人各踩一次**。

坑的经验有个特性：**它天然只存在当事人脑子里**。文档有人写，坑没人愿意写——写坑等于承认自己卡住过，过程往往也不体面（试了一堆错方向）。

所以这一节的写作要求里有一条：**必须写"当时试过什么、为什么不对"**。那部分才是别人真正用得上的东西。只写"最后加了个互斥锁"没有任何教育意义。

## 四、写一篇的要求

每篇按「现象 / 环境 / 原因 / 解决 / 验证 / 经验」六节写，其中三条是硬要求：

1. **现象要能被人认出来**：写症状，不写结论，并贴出可以原样搜索的报错原文。转述过的报错搜不到。
2. **原因要写到根因**：连着问三次"为什么"。只写到第二层，结论就会是"下次小心点"；写到第三层，才能变成"加一把锁"。
3. **经验要能迁移**：写判断规则，让读者遇到长得完全不一样的新问题时也能用上。
