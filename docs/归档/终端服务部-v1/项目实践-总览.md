# 项目实践

**这一类回答"一个项目怎么做"**，而且要求做到**能被别人从零复现**。

## 什么算一个项目

**有目标、有产出、结束时有明确状态的一件事**才算项目；只是"用过某个工具"，不算。判断标准：

- 有明确的**交付物**（一个能跑的服务、一套配置、一份报告、一个能演示的东西）。
- 有**验收方式**（怎么算做成）。
- 有**结束**（做完了、或者明确不做了）。

不满足这三条的，属于[技术模块](../技术模块/README.md)（一项技术的用法）或[技术经验](../技术经验/README.md)（一个坑的处理）。

## 每篇必须有的十一节

标题逐字保留，顺序不变（来自仓库根的 `SCHEMA.md` §4.1）：

```text
一、项目概述        六、核心代码
二、项目目标        七、项目实现
三、技术路线        八、复现步骤   ← 核心
四、开发环境        九、项目成果
五、硬件环境        十、已知问题
                    十一、后续方向
```

### 为什么「八、复现步骤」是核心

知识库里最容易变成废纸的就是项目文档。判断一份项目文档有没有用的唯一标准是：**一个没参与过的人，能不能照着它把东西做出来。**

所以第八节必须逐条回答六个问题：

| 子问题 | 要写到什么程度 |
| --- | --- |
| 准备什么 | 硬件、账号、权限、前置知识；缺哪一样会卡住 |
| 装什么 | 依赖与版本；命令能原样粘贴 |
| 配什么 | 配置项与取值；哪些必须改、哪些保持默认 |
| 跑什么 | 启动命令与顺序 |
| 预期结果 | 看到什么算正常（截图或日志片段） |
| 如何判定成功 | 一个具体的验证动作，不是"看起来没问题" |

文档里凡是不适用的地方，**保留标题写"不适用"并说明原因**，不要删标题。

## 新增一个项目

```powershell
node scripts/new.mjs 项目实践 docs/部门/终端服务部/项目实践/<项目名>
```

模板在 `_templates/项目README模板.md`。项目结束后另外写一份复盘，用 `_templates/项目复盘模板.md`，放在[历史与交接](../历史与交接/README.md)下。
