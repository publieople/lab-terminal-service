# 知识库规范（v2）

> 这份文件是本库**唯一权威**的结构约定。给人和 AI 的操作版分别在 `CONTRIBUTING.md` 和 `AGENTS.md`，机器契约在 `_schema/pages.json`。v1 的 `SCHEMA.md`、旧 `CONTRIBUTING.md`、8 个旧模板与 `_模板使用说明.md` 已收进 `docs/归档/规范与模板-v1/`，只作对照。

## 一、一句话

一个部门的知识库 = **四条内容线 + 管理页 + 记录**。每页以 YAML front-matter 开头，目录名就是分类，索引表与导航由脚本从 front-matter 生成。

## 二、优先级

发生冲突时按这个顺序：

```text
本文件（结构与字段）
  > AGENTS.md 第三节（安全与硬规则）
    > AGENTS.md 第一节（表达）
      > 归档里的 v1 文件（仅作参考）
```

## 三、目录结构

```text
docs/
├─ index.md                      站点首页
├─ 规范/                          本库的规范（本文件 + 实验室母规范）
├─ 归档/                          不再维护的旧内容，整棵搬入
└─ 部门/终端服务部/
   ├─ README.md                  部门介绍（整章入口）
   ├─ 招新介绍.md
   ├─ 职责与服务目录.md
   ├─ 待补事实.md
   ├─ 学习/                       ① 有序：有先后关系的课程线
   │  ├─ README.md                路线图（章节顺序 + 前置 + 验收）
   │  ├─ 01-Windows基础/
   │  │  ├─ README.md             本章导览
   │  │  ├─ 01-文件与路径.md
   │  │  └─ 02-快捷键与窗口.md
   │  ├─ 02-终端环境/
   │  └─ 03-Linux基础/
   ├─ 参考/                       ② 无序：一门技术、一个主题一页，按需查
   ├─ 项目/                       ③ 做出来的东西：一个项目一页
   ├─ 经验/                       ④ 踩过的坑：一坑一篇
   ├─ 历史与交接/                  记录：人员、设备、系统的变动
   └─ assets/                     本部门用到的图片等
```

四条线怎么分：

- **有先后顺序、要教人 → `学习/`**
- **没有顺序、要查 → `参考/`**
- **我们做出来的 → `项目/`**
- **我们炸过的 → `经验/`**

## 四、页面类型（6 个）

| `type` | 用在哪 | 必填章节（逐字） |
| --- | --- | --- |
| `课程` | `学习/` 下的每一讲 | 一、学习目标 / 二、前置 / 三、正文 / 四、练习 / 五、验收标准 / 六、下一讲 |
| `参考` | `参考/` 下的每一页 | 一、是什么 / 二、什么时候用 / 三、怎么做 / 四、常见问题 / 五、相关 |
| `项目` | `项目/` 下的每一页 | 一、项目目标 / 二、环境 / 三、复现步骤 / 四、成果 / 五、已知问题 / 六、用到的技术 |
| `经验` | `经验/` 下的每一页 | 一、现象 / 二、环境 / 三、原因 / 四、解决 / 五、验证 / 六、经验 |
| `记录` | `历史与交接/` | 自由 |
| `管理` | 部门 README、招新介绍、职责与服务目录、待补事实、各类索引 README、`规范/` 下的文件 | 自由；索引页的表格由脚本生成 |

章节标题必须**逐字**出现，顺序按上表。某一节不适用时**保留标题**，正文写「不适用」并说明原因——下一个项目可能用得上，空白结构比缺失结构容易复用。

## 五、front-matter

```yaml
---
title: 文件与路径
type: 课程
部门: 终端服务部
维护人: publieople
更新: 2026-10-11
状态: 草稿                     # 草稿 | 可用 | 待修订
可见性: 公开                    # 公开 | 内部
难度: 入门                      # 入门 | 进阶 | 深入 | 待补
适用版本: Windows 11 24H2       # 软件/系统版本；没有版本概念写「不限」，不确定写「待补」
前置: [01-Windows基础/01-文件与路径.md]   # 选填
tags: [Windows, 文件系统, 路径]           # 选填
---
```

规则：

1. **永远必填的 7 个字段**：`title`、`type`、`部门`、`维护人`、`更新`、`状态`、`可见性`。
2. `难度` 与 `适用版本` 在 `课程`、`参考`、`项目` 三类里必填。值不确定时写 `待补`。
3. `更新` 只在**内容真的变了**时改；只改格式不算。
4. `状态: 待修订` 用来标记「曾经可用、现在已知过时」的页面——这是最重要的一档，它让过时变成可见状态。

## 六、命名与路径

1. 目录名、文件名一律用中文，与页面标题一致。
2. **有序线加序号**：章节 `01-Windows基础`，讲次 `01-文件与路径.md`；无序线（参考、项目、经验）不加序号。
3. 序号留两位，方便中间插入（`01` … `10`）。
4. **改名等于断链**：改名前后必须 `rg` 一遍全库引用，并跑一次 `mkdocs build --strict`。
5. 一页一事：单页 300–900 字，超了拆成两页。

## 七、每页的硬要求

1. **第一段回答「什么时候需要看这篇」**——读者要能在一屏内决定读不读。
2. **必须能验收**：课程写「学完能亲手做出来的一件事」，项目写「怎么算跑通」，参考页写「照着做会看到什么」。写不出验收标准的页面，通常说明内容还没想清楚。
3. **单一来源**：同一件事只在一个页面写正文，别处只放链接（两份正文一定会各自腐烂）。
4. **不写内网信息**：`<内网IP>`、`<设备名>`、`<域名>`、`<用户名>` 占位；凭据、token、私钥永不入库。
5. 命令要能原样粘贴，并写清**在哪台机器、什么权限、什么目录**下执行。

## 八、索引与导航（全部由脚本生成，手改无效）

**索引表**：在类的 README 里放一对标记，脚本只重写标记之间的内容：

```markdown
<!-- gen:index 课程 01-Windows基础 -->
| 名称 | 一句话 | 难度 | 状态 | 更新 |
| --- | --- | --- | --- | --- |
| _还没有页面_ | — | — | — | — |
<!-- /gen:index -->
```

**导航**：一条命令生成三处，避免三份导航各自漂移。

```powershell
node scripts/gen-index.mjs     # 重写所有索引表
node scripts/gen-nav.mjs       # 重写 mkdocs.yml 的 nav 块、nav.片段.yml、SUMMARY.md
node scripts/check-pages.mjs   # 校验字段、章节，并列出三类待办
```

`check-pages.mjs` 会输出三份清单：**待迁移**（还是 v1 的字段/章节）、**待补字段**（`难度`/`适用版本` 写着 `待补`）、**待复核**（`更新` 超过 12 个月）。

## 九、可检索

1. `tags` 从固定词表里选（`_schema/tags.json`），不要临时造词。
2. 术语第一次出现时把常见同义词写在括号里：「终端（Terminal、命令行、shell）」。站点搜索按文字匹配，**同义词只能靠正文带上**。
3. 标题用读者会搜的词，不用内部代号。

## 十、归档

1. 不再维护的整块内容搬进 `docs/归档/<名字>/`，**整棵搬**，这样内部相对链接仍然可用。
2. 归档内容不进导航、不参与章节校验，但随仓库保存，随时能搜。
3. 每个归档目录的 README 首段写清：归档时间、为什么归档、替代它的新页面。

## 十一、加一页（人）

```powershell
node scripts/new.mjs 课程 docs/部门/终端服务部/学习/01-Windows基础/03-环境变量
node scripts/gen-index.mjs
node scripts/gen-nav.mjs
npx markdownlint-cli2
node scripts/check-pages.mjs
node scripts/check-secrets.mjs
.\.venv\Scripts\mkdocs.exe build --strict
```

`new.mjs` 会按类型套模板、建目录、把 `更新` 填成今天。

## 十三、和 v1 的差异（给审核的人）

| 项 | v1 | v2 |
| --- | --- | --- |
| 内容分类 | 6 类，`基础知识` 与 `技术模块` 的边界模糊 | 4 条线（学习 / 参考 / 项目 / 经验）+ 记录 |
| 顺序表达 | 无法表达"先学哪个" | 学习线用章节目录 + 两位序号 |
| 索引表 | 手写，六张表六种表头 | 脚本生成，列固定，永远不会漏更新 |
| 导航 | `mkdocs.yml` / `nav.片段.yml` / `SUMMARY.md` 三处手改 | 三处都由脚本生成，CI 比对 |
| 适用范围 | 没有这个字段 | `适用版本` |
| 验收标准 | 只在「四能」里当口号 | 每页一节，可判定 |
| `type` 数量 | 9 个 + 2 类靠路径豁免 | 6 个 |
| 过期处理 | 写在规范里，没有实现 | `check-pages.mjs` 直接列出待复核清单 |
