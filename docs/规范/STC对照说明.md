# STC 对照说明（简明技术性中文）

> 这份文件说明本库怎么用 STC：哪些规则照做，哪些不适用，为什么。规则正文、词表和检查器在 `skills/stc/`（来源、文件清单与快照指纹见该目录的 `README.md`），给 AI 的操作约束在 `AGENTS.md` 第一节。本文件与 `AGENTS.md` 冲突时以 `AGENTS.md` 为准。

## 一、STC 管什么

STC（Simplified Technical Chinese，简明技术性中文）是给 AI 写中文用的一套规则、两张词表和一个本地检查器。上游是 [daimonia-ai/STC-Simplified-Technical-Chinese](https://github.com/daimonia-ai/STC-Simplified-Technical-Chinese)。

它和 `humanizer-zh` 分工不同，两套一起用：

| | 管什么 | 看什么 |
| --- | --- | --- |
| `humanizer-zh` | 读起来像不像人写的 | 空话、重复、模板腔 |
| STC | 读起来像不像技术文档 | 空壳动词、模糊量词、营销词、提醒分级 |

先按 `humanizer-zh` 把话写顺，再按 STC 通读一遍。两套都只改表达。

规则分两层：`rules/for-all.md` 是通用规则（编号 G），`rules/for-document.md` 是文档场景（编号 D），另有聊天、网页、给 AI 的指令三套场景。检查器按 `--profile` 选一套。

## 二、本库照做的规则

| 规则 | STC 的要求 | 本库怎么用 |
| --- | --- | --- |
| G4 动作写成动词 | 删掉「进行」「加以」「实现」这类空壳动词 | 照做。「与操作系统进行交互」改成「与操作系统交互」 |
| G5 含糊的说法换成能核实的说法 | 「部分」「若干」「优化」要么给数字，要么说清指什么 | 只改能说清的。查不到依据就保持原样，并去 [待补事实](../部门/终端服务部/待补事实.md) 登记。**不得为了通过检查而编数字** |
| G6 禁营销词和行话 | 词表里的「赋能」「打造」「一站式」「无缝」「极致」，以及「沉淀」「落地」「对齐」「闭环」 | 照做，正文里出现即改 |
| G7 禁口号句式 | 「让我们……」「标志着……新时代」 | 照做 |
| D2 结论先行 | 先写结论，再写依据 | 照做。复盘和故障排查页尤其适用 |
| D4 三项以上用列表 | 三项并列写成列表 | 照做 |
| D5 步骤一步一个动作 | 一步只写一个动作 | 照做，操作类页面适用 |
| D6 风险提示先动作后后果 | 先写要做什么，再写不做会怎样 | 照做 |
| D7 提醒分三级，标签固定 | 只用「警告」「注意」「说明」 | 照做，新写的页面用这三个标签 |
| D8 提交信息第一行写改动 | 第一行是动词开头的改动摘要 | 照做，见 `AGENTS.md` 第三节第 7 条 |
| G19 中英文之间加空格 | 中文与英文、数字之间留空格 | 照做，见 `AGENTS.md` 第三节第 6 条 |
| I1 强度词只用固定的几个 | 「必须、不得、宜、不宜、可、不必、能、不能」 | 照做，用在 `AGENTS.md` 这类给 AI 的指令里；正文不套这套词 |
| I2 「必须」不与「尽量」连用 | 两者择一 | 照做 |

## 三、本库不适用的规则

| 规则 | STC 的要求 | 为什么不适用 |
| --- | --- | --- |
| D1 主语写名称 | 写「本部门」「本库」，不写「我们」 | 本库有复盘、招新介绍、部门介绍这类页面，「我们」就是叙述主体。只在规范、契约、操作步骤这类页面按 D1 写 |
| G12 一句不超过 40 字 | 每句控制在 40 字内 | 中文技术句常带限定条件，硬切会拆散因果。当作提醒用：一句话读不完就拆两句，不按字数机械执行 |
| G5 的后半条：无数据时写占位符 | 原文没有数字或事实时，正文里必须写「【待补：…】」 | 本库把缺的事实集中登记在 [待补事实](../部门/终端服务部/待补事实.md)，正文里满屏占位符会打断阅读。正文只说能说清的部分，确属事实缺口的登记到那一页 |
| G17 引号统一用全角双引号 | 直角引号「」与 ASCII 直引号都算违规，要改成 `“”` | 本库一直用「」标注词条和句式，全库 310 处；换成弯引号只是换符号，读者不会因此更清楚。**保留「」。** ASCII 直引号另说：新写的正文不用（`AGENTS.md` 第三节第 8 条），老页面改到那一段时顺手换掉 |
| G20 复核括号里的排除说明 | 括号里的「不是 A 而是 B」这类自证要复核 | 本库括号里常见「（不做会掉线）」这类补充说明，逐条复核收益低。只在正式操作步骤里照做 |
| 其余通用规则 | G1–G22 中未列入上表的 | 按上下文判断，不强制 |
| 接进 CI | 上游 CLI 可以接成一道检查门 | 不接。本库页面混着课程、复盘、招新介绍，检查器按产品说明书的语料写成，误报多（数字见第四节）。只在通读和审稿时手动跑 |

## 四、检查器在本库的实测

2026-10-14 用 `--profile for-document` 跑的结果：

| 范围 | 页面数 | 命中 | 其中真问题 |
| --- | --- | --- | --- |
| `docs/部门/终端服务部/` | 40 | 1230 | 约 200 |
| `docs/规范/` | 2 | 59 | 19 |
| `AGENTS.md`（用 `--profile for-instruction-writing`） | 1 | 49 | 19 |

命中最多的三类都是体裁问题，不是真问题：引号（G17，580 处，其中 ASCII 直引号 394、直角引号 186）、主语（D1，251 处）、句长（G12，178 处）。真问题集中在空壳动词（G4，47 处）、含糊量词（G5，128 处里的一部分）和营销词（G6，18 处）。

误报长这样：

- `docs/部门/终端服务部/参考/Tailscale组网.md:125`：括号里的补充说明「（不做会莫名其妙掉线）」被判成自我论证（G20）。
- `docs/部门/终端服务部/参考/终端与命令行.md:275`：整段粘贴用的命令被 ASCII 引号包着，被判成中英文之间缺空格（G19）。
- `docs/部门/终端服务部/参考/开发经验.md:37`：「十分钟」被判成程度词「十分」——检查器按字面匹配，不认词边界。同类误报每轮都会出现，看到「哪个规则号 + 哪个词」对不上就先怀疑这个。

## 五、本轮的清理范围

2026-10-14 这一轮只清三类真问题，加上 `AGENTS.md` 里的强度词：

- G4 空壳动词
- G5 含糊说法（能说清的才改）
- G6 营销词与行话
- `AGENTS.md` 里的 I1 强度词：「不要」改「不得」，「建议」改「要」

不动三类体裁问题：引号（G17）、主语（D1）、句长（G12）。也不动 `docs/规范/文档写入规范.md`——它是外部导入件，正文按原样保留。

## 六、改完怎么复查

在仓库根目录：

```powershell
node skills\stc\tools\cli.mjs check docs\部门\终端服务部 --profile for-document
```

- 报告按规则分组，每条带行号和原文片段；建议由作者决定是否采用，退出码不表示有没有命中。
- 看到熟悉的规则号，先翻第三节，确认它是不是本库的不适用项。
- 确认是误报就保留原文。要长期压住某一行，在那一行上方写一行 HTML 注释 `<!-- stc-disable-next-line -->`，检查器会跳过它下面那一行。
- 只想看必须改的，加 `--no-warnings`；要机器可读的报告，加 `--json`。

## 七、快照怎么维护

上游提交号、文件清单、总字节数和聚合 SHA256 记在 `skills/stc/README.md`。更新时整份替换受影响文件，不要只改几段，然后同步那份记录。上游把规则正文放在 `rules/`，词表放在 `dictionary/`，检查器用的两份 JSON 由词表生成，本库不装依赖，所以改词表要回上游改。
